# Project status — TensorFlow-only consolidation

The active training, calibration, evaluation, Kaggle and test flows use TensorFlow. The original PyTorch source and notebook are preserved in the verified pre-consolidation backup under `backups/`; they are no longer active files. The previous local inventory found 3,077 train, 385 validation and 404 test MP4 videos across 100 labels, with zero cross-split groups of identical SHA256. No signer ID was available. See `dataset_counts.csv` for per-class counts; these are inventory results, not accuracy metrics.

The existing source implements a MediaPipe XY 54-landmark adaptation of Siformer. It keeps train-only RGB crop/color jitter before extraction, train-only temporal speed and inverse-frequency sampling, deterministic validation/test, validation-selected best checkpoint, optional validation-calibrated early exit, full TensorFlow resume state and once-only test evaluation. Rectification remains off by default because verified motion tables are absent. No compatible pretrained weights are provided.

After consolidation, `python -m unittest tests.test_pipeline -v` passed **7/7** on local TensorFlow 2.18.1 CPU. Checks cover model forward/backward, frozen reference comparison (maximum logit difference 3.8743e-7; ProbSparse difference 4.4703e-8), augmentation/sampling, checkpoint/resume and synthetic train/calibration/test/bundle. Static Python/JSON/notebook checks passed; importing all active entry points left `torch` absent from `sys.modules`. These do not establish real VSL accuracy. The local test environment lacks MediaPipe, OpenCV, scikit-learn and the `tensorflow` package metadata (it uses `tensorflow_cpu`); `requirements.txt` still needs installation in a complete preprocessing environment. Full landmark extraction, full VSL training, real test evaluation and Kaggle GPU/mixed-precision behavior remain unverified until explicitly run. The archived [migration report](TENSORFLOW_MIGRATION_REPORT.md) records the pre-consolidation numerical evidence.
